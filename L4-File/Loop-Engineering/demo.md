



| 代码模块 | 对应循环五要素 | 作用说明 |
| :--- | :--- | :--- |
| TASK_GOAL / PASS_SCORE | 明确目标 + 终止条件 | 划定任务范围、设置停止规则，避免无限循环 |
| context 列表 | 上下文管理 | 留存每一轮输出 + 建议，AI 延续历史信息迭代 |
| 主逻辑调用模型 | 工具 / 执行能力 | 此处为基础文本生成，可扩展调用本地代码、API、文件读写等工具 |
| evaluate_result() | 结果评估 | 自动质检、打分、产出优化方向，是循环的核心驱动力 |
| MAX_LOOP + 分数判断 | 安全终止机制 | 双重防护，杜绝死循环、错误叠加 |

扩展玩法（进阶改造方向）
1. 增加本地工具调用（代码运行校验）
结合 exec() / 子进程，自动运行代码验证是否报错，把运行结果回传给 AI，实现「写代码→跑代码→排错」全自动循环。
2. 多 Agent 分工循环
拆分角色：
执行 Agent：负责产出内容
评估 Agent：专职质检打分
优化 Agent：接收建议并修改
实现多角色协作循环。
3. 持久化记忆
将每轮日志、经验写入本地 log.md，下次任务加载历史记录，实现长期知识沉淀。
4. 适配复杂长任务
修改 TASK_GOAL，可用于：文档改写、数据分析、自动化测试、需求拆解等长周期任务。

使用注意事项
Token 消耗：循环轮次越多、上下文越长，消耗越高，简单任务不建议用循环；
模型选择：评估环节优先用强逻辑模型，弱模型容易打分失真、循环跑偏；
死循环兜底：MAX_LOOP 必须配置，这是 Loop 工程的基础安全规范；
私有化部署：替换 base_url 即可对接本地大模型、私有 API。
